# 设计原则

> DearOreUI 遵循 9 条核心原则。它们决定了你写 Mod 时的体验：**简单、安全、可预测**。读完这一页，你会明白为什么 DearOreUI 的 API 长这样，以及它能为你兜住哪些坑。

---

## 1. 声明式优先：告诉它"要什么"，而不是"怎么做"

你只需要描述"我想要一个居中的提示框"，剩下的注入、渲染、生命周期全部由DearOreUI负责。你不需要重复造轮子。

```cpp
// ✅ 声明式：描述"要什么"
UiManifest ui;
ui.kind       = UiKind::Overlay;
ui.anchor     = UiAnchor::Center;
ui.pageScopes = {PageScope::Any};

oreui->registerOverlay(modId, ui, "<div>Hello, DearOreUI!</div>");
```

```cpp
// ❌ 命令式：自己动手"怎么做"（需要懂引擎内部，容易崩）
auto* view = captureView();
view->ExecuteScript("document.createElement('div')...");
```


## 2. 零侵入：你的 Mod 不会弄坏游戏

DearOreUI 不修改游戏安装目录、不替换原版资源、不改原版页面。你的 Mod 失败时，游戏保持原样。

| 特性 | 说明 |
| --- | --- |
| 不修改游戏文件 | 所有注入都在运行时内存中完成，磁盘上的原版文件原封不动 |
| 失败自动回退 | 页面加载失败时零副作用，游戏照常运行 |
| 失败隔离 | 一个 Mod 失败不影响其他 Mod；一个页面失败不影响其他页面 |

你可以放心地在正式环境里试错——最坏情况只是"你的 UI 没显示"，而不是"游戏崩了"。

## 3. 渐进式难度：从简单开始，按需升级

普通 Mod 只需要声明式注册；只有需要页面生命周期、游戏能力或原版代码变换时才升级。API 按难度逐级开放：

```text
L0 查询运行时        —— 只读，零副作用（isReady / capabilities）
L1 注册资源与 UI     —— 声明式，普通 Mod 停在这里
L3 挂载 UI           —— Overlay / Panel / Button / Page
L6 高级兼容          —— vtable 指纹、多版本 ABI 适配
```

你不需要一上来就理解整个架构。90% 的场景停在 L1，剩下的按需学习。

## 4. 语义化变体：说"说明操作"，不说"蓝色按钮"

变体用**语义命名**（primary / secondary / neutral / destructive），不要用视觉描述（solid / flat / bordered）。代码表达意图，主题变化时无需改代码。

```cpp
// ✅ 语义化：表达意图
button.variant = "primary";      // 主操作，推进流程
button.variant = "secondary";    // 次要操作
button.variant = "destructive";  // 危险操作（删除等）
```

| 变体 | 用途 | 建议 |
| --- | --- | --- |
| `primary` | 主操作，推进流程 | 每个上下文 1 个 |
| `secondary` | 次要操作 | 可多个 |
| `neutral` | 中性操作 | 默认 |
| `destructive` | 危险操作（删除、清空） | 按需 |

代码可读、可维护；换主题时变体含义不变，UI 自动跟随。

## 5. 可预测行为：所有组件遵循同一套规则

所有组件共享同一个规格（`ComponentSpec`）：同样的字段、同样的状态、同样的渲染链路。学会一个，就会全部。

```cpp
// 所有组件都用同一套字段
ComponentSpec spec;
spec.kind     = ComponentKind::Button;  // 或 Panel / Text / Card / Input ...
spec.label    = "OK";
spec.variant  = "primary";
spec.disabled = false;
spec.state    = "default";              // default / hovered / focused / pressed / disabled
```

你不用为每个组件重新学一套 API；组件之间可以自由嵌套组合。

## 6. 可诊断：出问题时有据可查

每个注册、注入、失败事件都会写入诊断文件，带时间戳、严重级别、所属 Mod 和错误码。排查问题先看诊断，不靠猜。

```text
{"id":"...","timestamp":"...","severity":"error","category":"mount",
 "modId":"my-first-ui","pageId":"/play/all","errorCode":"CONFLICT", ...}
```


## 7. 冲突显式：不静默覆盖

多个 Mod 同时改同一个页面时，冲突会**显式报错**，而不是静默覆盖。每个注册返回 `Result`，错误可处理。

```cpp
auto result = oreui->registerOverlay(modId, ui, html);
if (result.isErr()) {
    // 冲突、校验失败、无效参数——都有明确的错误码
    log(result.error());
}
```

多 Mod 协作时，你的 UI 不会被别人悄悄顶掉；有冲突第一时间暴露，不是上线后才发现。

## 8. 原版风格：观感与原版一致

组件直接复用原版主题变量和原版纹理，你的 UI 和原版界面看起来**一模一样**，而不是"像网页"。

```cpp
// 按钮直接使用原版 pressable 纹理，而非近似 CSS
button.variant = "primary";
// → border-image: url(/hbui/assets/...) 9-slice 渲染
```

不用去"模仿"原版！内置丰富组件库，开箱即用。

## 9. AI 友好：能力矩阵机器可读

运行时公开能力矩阵，AI 可以查询"运行时到底支持什么"，只生成可用的代码，不生成运行时不可用的 API。

```text
capabilities: {
  "ui.mount":        "supported",
  "host.call":       "experimental",
  "transform.bundle":"unsupported"
}
```

AI 辅助开发时，生成的代码与运行时能力严格对齐；契约先行，文档示例与源码逐一对应。
